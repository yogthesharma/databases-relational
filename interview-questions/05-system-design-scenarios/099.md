# Question 099: Distributed Cron and Exactly-One Scheduler

## Context
Hundreds of app nodes must run scheduled jobs (rotate keys, settle batches). Overlap is harmful. You may use PostgreSQL as the coordination store.

## Interviewer Prompt
1. Design a leasing/locking schema so only one node runs each job per schedule tick.
2. How do you handle node death mid-job (visibility timeout / heartbeat)?
3. Compare this to external schedulers (Kubernetes CronJob, dedicated queue) and when DB coordination is enough.
