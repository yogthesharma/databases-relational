# Question 089: Idempotent Payment Capture Under Retries

## Context
Payment webhooks and client retries can deliver the same `capture` intent multiple times. You must debit a wallet at most once per `idempotency_key` while recording a ledger entry.

```sql
CREATE TABLE wallet_ledger (
  id               bigserial PRIMARY KEY,
  wallet_id        bigint NOT NULL,
  idempotency_key  text NOT NULL,
  amount_cents     integer NOT NULL,
  UNIQUE (wallet_id, idempotency_key)
);
```

## Interviewer Prompt
1. Design the transactional flow for idempotent capture.
2. How do you handle concurrent duplicates arriving on two app nodes?
3. What do you return to callers for first success vs duplicate replay?
