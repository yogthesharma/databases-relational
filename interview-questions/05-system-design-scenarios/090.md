# Question 090: Inventory Reservation for Flash Sales

## Context
A flash sale offers 1,000 units. Traffic is 100k users hammering "reserve." Oversell is unacceptable. Experience should fail fast when sold out.

## Interviewer Prompt
1. Design a reservation scheme using PostgreSQL (tables, transactions, locks or atomic counters).
2. Compare row-per-item, counter shard, and `SKIP LOCKED` ticket-pool approaches.
3. How do short-held reservations expire without double-selling?
