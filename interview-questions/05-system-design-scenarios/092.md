# Question 092: Exactly-Once Processing with an Outbox

## Context
After committing an order, you must publish `OrderCreated` to Kafka. Publishing before commit risks ghost events; after commit risks lost events if the process dies.

## Interviewer Prompt
1. Design the transactional outbox pattern on PostgreSQL.
2. How does a publisher drain the outbox with `SKIP LOCKED` safely?
3. What consumer idempotency is still required downstream?
