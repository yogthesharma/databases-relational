# Question 086: High-Throughput Leaderboard Updates

## Context
A game needs a global leaderboard updated on every match end (~50k writes/sec at peak). Readers fetch top 100 and a player's rank. A first prototype does:

```sql
UPDATE scores SET points = points + $1 WHERE player_id = $2;
SELECT player_id FROM scores ORDER BY points DESC LIMIT 100;
```

Hot players and the sorted read contend badly.

## Interviewer Prompt
1. Critique the prototype under peak write and read load.
2. Propose an architecture (DB tables, caches, async aggregation) that meets rank freshness within a few seconds.
3. How do you prevent leaderboard cheating and ensure replayable score audits?
