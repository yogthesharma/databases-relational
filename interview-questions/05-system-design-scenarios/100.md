# Question 100: Degraded Mode When Primary Is Unavailable

## Context
The primary Postgres is down for 10 minutes during a cascading cloud failure. Product wants limited read-only browsing from replicas and to queue writes for later. Some writes are legally required to be acknowledged only after durability.

## Interviewer Prompt
1. Design application degraded modes distinguishing durable-required vs deferrable writes.
2. How do you safely serve reads from replicas during primary outage (lag, auth, RLS session context)?
3. What user communications and idempotency design make write replay after recovery safe?
