# Question 078: Read Scaling with Lag-Aware Routing

## Context
An API routes 80% of reads to replicas. Support tickets mention inconsistent list/detail pages. A middleware caches "replica lag seconds" but uses a single global threshold.

## Interviewer Prompt
1. Design lag-aware routing that still protects UX for read-after-write sessions.
2. What metrics define "safe enough" lag for different endpoints?
3. When do you stop scaling reads with replicas and shard or cache instead?
