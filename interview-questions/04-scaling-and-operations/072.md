# Question 072: Cross-Region Read Replica Lag and Write Strategy

## Context
We are deploying a globally distributed application with a primary PostgreSQL instance in `ap-south-1` (Mumbai) and a physical read-replica in `us-east-1` (N. Virginia).

When a user in the US updates their profile details and is immediately redirected to their dashboard, they frequently observe stale data for 200ms to 1.5 seconds.

## Interviewer Prompt
1. Explain the underlying engine mechanism causing this stale read behavior.
2. How would you architect the application connection layer to guarantee a "read-your-own-writes" consistency model for the user without routing 100% of global read traffic back to the Mumbai primary?
3. If the product team demands that US users must also execute local writes with sub-20ms latency, what structural limitations in native PostgreSQL prevent this, and what architectural options exist to support multi-region writes?
