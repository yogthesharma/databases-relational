# Question 074: Online Index Creation and Write Overhead

## Context
You need a new composite index on a 200GB table. `CREATE INDEX CONCURRENTLY` runs for hours. Writes slow somewhat; the deploy pipeline is unsure when it is safe to continue.

## Interviewer Prompt
1. Explain how `CONCURRENTLY` avoids long AccessExclusive locks and what phases it runs.
2. What happens if the session is canceled mid-build?
3. How do you monitor progress and decide the write amplification is acceptable?
