# Question 066: PgBouncer Pooling Modes and App Compatibility

## Context
You are introducing PgBouncer in front of PostgreSQL because `max_connections` exhaustion is causing outages. App features use prepared statements, temp tables, and `LISTEN`.

## Interviewer Prompt
1. Contrast session, transaction, and statement pooling modes.
2. Which app features break under transaction pooling, and how do you mitigate?
3. How do you size server connections vs client pool sizes across many app nodes?
