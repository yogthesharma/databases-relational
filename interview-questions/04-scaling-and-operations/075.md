# Question 075: Failover Orchestration and Split Brain

## Context
Patroni/repmgr-style automation promotes a standby when the primary is unreachable from the DCS. Network partitions can make the old primary still accept writes. Fencing is incomplete.

## Interviewer Prompt
1. Explain split-brain risk after automatic failover.
2. What fencing / STONITH / connection routing controls are required?
3. How should applications handle brief read-only windows and connection rewiring?
