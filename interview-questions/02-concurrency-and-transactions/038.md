# Question 038: Optimistic Concurrency with Version Columns

## Context
Document editing uses:

```sql
UPDATE docs
SET body = $1, version = version + 1
WHERE id = $2 AND version = $3;
```

Clients retry on zero-row updates. Conflict rate is high for a few hot documents.

## Interviewer Prompt
1. Explain how this implements optimistic concurrency control.
2. Compare UX and server load of retries versus `SELECT FOR UPDATE` on hot documents.
3. When would you introduce CRDTs or operational transforms instead of row versioning?
