# Question 030: Row-Level Locks: FOR UPDATE vs FOR SHARE

## Context
A checkout flow locks a inventory row before decrementing quantity. Engineers debate `FOR UPDATE`, `FOR NO KEY UPDATE`, `FOR SHARE`, and `FOR KEY SHARE`.

## Interviewer Prompt
1. Explain what each row lock mode allows and blocks regarding concurrent `UPDATE`, `DELETE`, and FK checks.
2. Which mode would you pick for inventory reservation, and which is over-restrictive?
3. How do these locks interact with `FOREIGN KEY` checks from child tables?
