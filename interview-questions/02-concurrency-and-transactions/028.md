# Question 028: MVCC Visibility and Row Versions

## Context
A long-running `REPEATABLE READ` analytics transaction started at T0. Meanwhile OLTP updates the same rows many times. The analyst's query still sees "old" data. Table size on disk grows; autovacuum lags.

## Interviewer Prompt
1. Explain how MVCC tuple versions and snapshots produce this behavior.
2. Why can long-running transactions accelerate table bloat?
3. What monitoring would you use to find snapshot-holding backends before they hurt the cluster?
