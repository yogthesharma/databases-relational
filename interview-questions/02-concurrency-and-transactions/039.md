# Question 039: FK Checks and Locking Behavior

## Context
Inserting into `order_items` references `orders(id)`. Under concurrency, parent updates (e.g., touching `updated_at`) and child inserts occasionally block each other longer than engineers expect. Deleting parents with large child sets also locks heavily.

## Interviewer Prompt
1. Describe the locks taken for FOREIGN KEY validation on insert and delete.
2. How can updating a parent PK/unique key column cause surprising contention?
3. What schema practices reduce FK-related lock pain at scale?
