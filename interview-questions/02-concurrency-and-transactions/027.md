# Question 027: Isolation Levels: Read Phenomena Catalog

## Context
An interviewer asks you to relate SQL isolation levels to phenomena: dirty read, non-repeatable read, phantom read, write skew.

Your production default is PostgreSQL `READ COMMITTED`.

## Interviewer Prompt
1. Define each phenomenon and state which PostgreSQL isolation levels prevent it.
2. Give a realistic application bug that appears under `READ COMMITTED` but not under `REPEATABLE READ` or `SERIALIZABLE`.
3. What operational costs (retries, conflicts) appear as you strengthen isolation?
