# Question 026: ACID in Practice for a Funds Transfer

## Context
You are designing a ledger transfer between two accounts in PostgreSQL. Product requirements: never create or destroy money; never show a partial transfer to readers; survive process crashes mid-operation.

```sql
CREATE TABLE accounts (
  id       bigserial PRIMARY KEY,
  balance  numeric(18,2) NOT NULL CHECK (balance >= 0)
);
```

## Interviewer Prompt
1. Map Atomicity, Consistency, Isolation, and Durability onto concrete choices in this transfer design.
2. Which invariants belong in DB constraints versus application code?
3. What failure scenarios (crash after debit, client retry, double submit) must your transaction boundaries handle?
