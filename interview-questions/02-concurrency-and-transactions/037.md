# Question 037: Idle in Transaction and Connection Pool Abuse

## Context
Monitoring shows many sessions `idle in transaction` for minutes. Row versions cannot be vacuumed; lock waits increase. The app uses an HTTP request-scoped transaction that includes outbound payment API calls.

## Interviewer Prompt
1. Why is `idle in transaction` particularly harmful under MVCC?
2. Redesign the transaction boundary relative to external I/O.
3. What pooler and server settings help detect or limit this class of bug?
