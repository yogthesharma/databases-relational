# Question 044: Prepared Transactions and Two-Phase Commit

## Context
A rare integration path uses `PREPARE TRANSACTION` across PostgreSQL and another system. Ops finds orphaned prepared transactions holding locks and preventing vacuum.

## Interviewer Prompt
1. Explain 2PC's `PREPARE` / `COMMIT PREPARED` model and failure modes.
2. Why are prepared transactions operationally hazardous in PostgreSQL estates?
3. What alternatives would you prefer for most cross-system consistency needs?
