# Question 033: Table-Level Locks and DDL Collisions

## Context
A migration runs `ALTER TABLE ... ADD COLUMN ... DEFAULT ...` (pre-PG11 mental model vs modern behavior) during peak traffic. Application queries pile up behind `AccessExclusiveLock`. Separately, a `CREATE INDEX` without `CONCURRENTLY` locks writes.

## Interviewer Prompt
1. Explain which common DDL operations take heavy locks and why apps queue behind them.
2. How do modern PostgreSQL versions reduce lock strength for some `ADD COLUMN` cases?
3. Design a migration checklist that prevents surprise AccessExclusiveLock outages.
