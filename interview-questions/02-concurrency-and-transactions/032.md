# Question 032: Deadlocks: Detection and Design

## Context
Production logs show:

```
ERROR: deadlock detected
DETAIL: Process 42 waits for ShareLock on transaction 100; blocked by process 43.
Process 43 waits for ShareLock on transaction 99; blocked by process 42.
```

Two services update `orders` and `order_items` in opposite table order.

## Interviewer Prompt
1. Walk through how PostgreSQL detects and resolves deadlocks.
2. What deterministic locking order guidelines would you impose across services?
3. How do client retry strategies need to differ for deadlock aborts versus serialization failures?
