# Question 036: Transaction Nesting and Savepoints

## Context
A service uses an ORM that opens a transaction per request. Inside, a library catches errors and continues. Developers are surprised that a failed statement aborts the whole PostgreSQL transaction unless savepoints are used.

## Interviewer Prompt
1. Explain PostgreSQL's transaction abort state after an error mid-transaction.
2. How do `SAVEPOINT` / `ROLLBACK TO` change control flow for partial recovery?
3. What pitfalls appear when ORMs silently emit savepoints or swallow DB errors?
