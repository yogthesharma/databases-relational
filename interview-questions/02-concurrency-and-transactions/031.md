# Question 031: FOR UPDATE SKIP LOCKED for Work Queues

## Context
You are building a job queue in PostgreSQL:

```sql
SELECT id, payload
FROM jobs
WHERE state = 'queued'
ORDER BY priority DESC, id
FOR UPDATE SKIP LOCKED
LIMIT 10;
```

Multiple workers claim jobs concurrently.

## Interviewer Prompt
1. Explain what `SKIP LOCKED` does compared to waiting on `FOR UPDATE`.
2. What transaction boundaries are required so a crash cannot lose or double-process a job?
3. What fairness / starvation issues can arise with this pattern under skewed priorities?
