# Question 029: Lost Updates Under READ COMMITTED

## Context
Two concurrent sessions run:

```sql
-- both read balance 100, both compute 100+10, both write 110
UPDATE accounts SET balance = balance + 10 WHERE id = 1;  -- vs read-modify-write in app
```

Some services do `SELECT` then `UPDATE` in application code without locking.

## Interviewer Prompt
1. Demonstrate how a lost update can occur with naive read-modify-write at `READ COMMITTED`.
2. Compare fixing it with `UPDATE ... SET balance = balance + 10`, `SELECT FOR UPDATE`, and optimistic version columns.
3. Which approach would you choose for a high-contention counter and why?
