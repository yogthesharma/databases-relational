# Question 040: Explicit Locking of Multiple Rows Safely

## Context
A transfer must lock two account rows then update both. Naive code locks `from_id` then `to_id` in argument order. Deadlocks appear when transfers run in opposite directions.

## Interviewer Prompt
1. How should you order row locks to make multi-row updates deadlock-resistant?
2. Write the locking + update sequence you want reviewers to insist on (conceptually).
3. How does this interact with `SKIP LOCKED` if you were building a matching engine instead of a ledger?
