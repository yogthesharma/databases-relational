# Question 004: Partial Indexes for Hot Predicates

## Context
Ninety percent of production queries against `jobs` look like:

```sql
SELECT id, payload, attempts
FROM jobs
WHERE state = 'queued'
ORDER BY priority DESC, id ASC
LIMIT 50;
```

Historical rows in `state IN ('done','failed')` dominate the table. Someone proposes a full index on `(state, priority, id)`.

## Interviewer Prompt
1. Critique the full composite index for this workload.
2. Propose a partial index definition and explain when the planner can and cannot use it.
3. What operational risks appear if application code starts querying `state = 'queued' OR state = 'running'` against that partial index?
