# Question 003: Index-Only Scans and Heap Fetches

## Context
A read-heavy endpoint only needs three columns from a large `events` table:

```sql
SELECT user_id, event_type, created_at
FROM events
WHERE user_id = $1
  AND created_at >= $2
ORDER BY created_at DESC
LIMIT 100;
```

`EXPLAIN ANALYZE` after adding `(user_id, created_at)` shows an Index Scan with a large "Heap Fetches" count. Another engineer suggests a covering index including `event_type`.

## Interviewer Prompt
1. Explain what a heap fetch is in PostgreSQL and why it appears even when an index matches the filter.
2. How do visibility information and `VACUUM` relate to whether an Index Only Scan stays "index only"?
3. Design the covering index you would propose and state the tradeoffs (write amplification, disk, update patterns on `event_type`).
