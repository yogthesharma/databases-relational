# Question 023: Invalid / Unused Indexes After Migrations

## Context
`CREATE INDEX CONCURRENTLY` failed halfway during a deploy. Later, `\d table` shows an index marked `INVALID`. Separately, `pg_stat_user_indexes` shows several indexes with zero `idx_scan` for months.

## Interviewer Prompt
1. What does an `INVALID` index mean for reads and writes, and how do you repair it safely?
2. How would you decide an unused index is safe to drop in production?
3. What process would you add so concurrent index builds cannot leave silent INVALID indexes after deploys?
