# Question 005: GIN vs B-Tree for Array Containment

## Context
A product tagging feature stores tags as `text[]`:

```sql
CREATE TABLE products (
  id    bigserial PRIMARY KEY,
  name  text NOT NULL,
  tags  text[] NOT NULL DEFAULT '{}'
);

-- frequent query
SELECT id, name
FROM products
WHERE tags @> ARRAY['organic', 'gluten-free'];
```

An engineer adds a standard B-Tree on `tags`. Query plans remain sequential scans.

## Interviewer Prompt
1. Why is a B-Tree a poor fit for `@>` containment on arrays?
2. Which index type would you choose instead, and what operator class concerns would you verify?
3. How would you evaluate whether normalizing tags into a junction table plus B-Tree beats a GIN index for this product's write/read mix?
