# Question 012: JOIN Order, Nested Loop vs Hash Join

## Context
Two plans appear for the same join of `orders` (large) to `merchants` (small) depending on statistics freshness:

- Nested Loop with index on `orders.merchant_id`
- Hash Join building a hash of `merchants`

The query filters a date range on orders and joins merchant attributes for display.

## Interviewer Prompt
1. Explain when the planner prefers Nested Loop vs Hash Join for this pattern.
2. How can stale statistics or wrong `work_mem` push you into a catastrophic Nested Loop?
3. What would you inspect in `EXPLAIN (ANALYZE, BUFFERS)` to decide which plan is actually better for your cardinality?
