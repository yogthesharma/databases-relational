# Question 018: Upserts and Unique Indexes Under Contention

## Context
Ingestion uses:

```sql
INSERT INTO device_heartbeats (device_id, last_seen, meta)
VALUES ($1, $2, $3)
ON CONFLICT (device_id) DO UPDATE
SET last_seen = EXCLUDED.last_seen,
    meta = EXCLUDED.meta;
```

At peak, many workers upsert the same hot `device_id`s. Latency spikes and deadlocks appear occasionally with other writers touching related tables.

## Interviewer Prompt
1. Explain what locks `ON CONFLICT DO UPDATE` takes on conflicting rows.
2. How can hot-key upserts create throughput ceilings, and what application patterns reduce conflict rates?
3. When would you prefer "insert into a log table + async rollup" over in-place upsert?
