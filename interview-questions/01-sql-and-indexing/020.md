# Question 020: Hash Indexes and Equality-Only Lookups

## Context
A colleague proposes replacing a B-Tree on a UUID primary-key lookup path with a HASH index "because we only ever do equality." PostgreSQL version is current; WAL and replication are required.

## Interviewer Prompt
1. What are the historical and current caveats of HASH indexes in PostgreSQL?
2. For UUID equality PK lookups, when if ever would HASH beat B-Tree?
3. What operational concerns (replication, crash safety, uniqueness) would you verify before allowing HASH indexes in this estate?
