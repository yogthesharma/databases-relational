# Question 010: LATERAL Joins for Top-N-Per-Group

## Context
Product managers want: for each of the top 100 merchants by GMV this month, return their **three** most recent refunds.

An engineer drafts a window-function mega-query. Another proposes `JOIN LATERAL`.

Sample skeleton:

```sql
SELECT m.merchant_id, r.*
FROM top_merchants m
JOIN LATERAL (
  SELECT *
  FROM refunds r
  WHERE r.merchant_id = m.merchant_id
  ORDER BY r.created_at DESC
  LIMIT 3
) r ON true;
```

## Interviewer Prompt
1. Explain how `LATERAL` changes correlation and planner options versus a plain join.
2. What index makes the lateral subquery cheap per merchant?
3. Compare this pattern to window functions for top-N-per-group—when does each win on large datasets?
