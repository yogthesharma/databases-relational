# Question 016: Pagination: OFFSET vs Keyset

## Context
A mobile feed uses:

```sql
SELECT * FROM posts
WHERE author_id = $1
ORDER BY created_at DESC, id DESC
OFFSET $2 LIMIT 20;
```

Deep pages (`OFFSET` in the tens of thousands) are slow even with a good index.

## Interviewer Prompt
1. Explain why large `OFFSET` remains expensive despite an index.
2. Design a keyset (seek) pagination API and the corresponding SQL.
3. What correctness issues arise with keyset pagination under concurrent inserts/deletes?
