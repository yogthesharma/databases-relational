# Question 014: JSONB Indexing Strategies

## Context
Feature flags and sparse attributes live in `JSONB`:

```sql
CREATE TABLE accounts (
  id         bigserial PRIMARY KEY,
  attrs      jsonb NOT NULL DEFAULT '{}'
);

-- common filters
WHERE attrs @> '{"plan":"enterprise"}'
WHERE attrs->>'region' = 'eu'
WHERE (attrs->'limits'->>'seats')::int > 100
```

Three index proposals: GIN on `attrs`, B-Tree on `(attrs->>'region')`, expression B-Tree on the seats cast.

## Interviewer Prompt
1. Map each query shape to an appropriate index type and explain why.
2. What are the write and storage costs of a wide GIN on the entire `attrs` document?
3. When would you push a hot JSON key out into a real column instead of indexing JSONB?
