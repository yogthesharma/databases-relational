# Question 002: B-Tree Selectivity and Composite Index Order

## Context
You are reviewing a slow query that filters active subscriptions for a tenant and sorts by renewal date:

```sql
SELECT *
FROM subscriptions
WHERE tenant_id = $1
  AND status = 'active'
ORDER BY renews_at ASC
LIMIT 20;
```

Proposed indexes from two engineers:

- Engineer A: `(status, renews_at, tenant_id)`
- Engineer B: `(tenant_id, status, renews_at)`

`tenant_id` is highly selective. `status` has only four distinct values. Table has tens of millions of rows.

## Interviewer Prompt
1. Compare the two composite B-Tree proposals for this exact query shape. Which would you ship and why?
2. Explain how left-to-right column order in a B-Tree interacts with equality filters versus `ORDER BY`.
3. Under what workload change would you revisit this index design (e.g., new filters, different `LIMIT`, reporting queries)?
