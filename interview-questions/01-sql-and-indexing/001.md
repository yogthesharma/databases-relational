# Question 001: Reading EXPLAIN ANALYZE Under Load

## Context
Your team owns an orders API. A new dashboard endpoint that lists a merchant's last 50 orders by `created_at` feels fine in staging but times out under production traffic. An engineer pastes this plan fragment into Slack:

```
Seq Scan on orders  (cost=0.00..48521.00 rows=50 width=120)
  Filter: (merchant_id = $1)
  Rows Removed by Filter: 2_400_000
Planning Time: 0.4 ms
Execution Time: 812 ms
```

Relevant schema sketch:

```sql
CREATE TABLE orders (
  id           bigserial PRIMARY KEY,
  merchant_id  bigint NOT NULL,
  created_at   timestamptz NOT NULL,
  status       text NOT NULL,
  total_cents  integer NOT NULL
);
-- currently only the primary key index exists
```

## Interviewer Prompt
1. Walk me through what this plan is telling you, line by line, including what "Rows Removed by Filter" implies about work done.
2. What index (or indexes) would you propose, and why that shape rather than a single-column index on `merchant_id` alone?
3. After adding an index, what exact `EXPLAIN (ANALYZE, BUFFERS)` signals would convince you the fix is real under production-like data volume?
