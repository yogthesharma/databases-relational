# Question 021: BRIN for Append-Only Time Series

## Context
An IoT metrics table is insert-mostly, ordered by time:

```sql
CREATE TABLE sensor_readings (
  ts         timestamptz NOT NULL,
  sensor_id  int NOT NULL,
  reading    double precision NOT NULL
);
```

Queries almost always constrain a time window plus `sensor_id`. Someone suggests BRIN on `ts` instead of a large B-Tree.

## Interviewer Prompt
1. Explain how BRIN works and what physical clustering assumption it needs.
2. When is BRIN a win versus a B-Tree (or composite B-Tree) for this table?
3. What happens to BRIN effectiveness after heavy updates or unordered bulk loads?
