# Question 060: Domain Integrity with DEFERRABLE Constraints

## Context
A bulk import temporarily violates FK order (children before parents) within one transaction. Someone enables `DEFERRABLE INITIALLY DEFERRED` FKs. Another worries about long windows of invalid state.

## Interviewer Prompt
1. Explain immediate vs deferred constraint checking.
2. When are deferred constraints justified, and what risks do they introduce?
3. How would you structure the import transaction to keep deferral scope minimal?
