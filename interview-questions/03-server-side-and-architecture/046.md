# Question 046: Functions vs Procedures: Transaction Control

## Context
A team debates putting a multi-statement business workflow in a SQL `FUNCTION` versus a `PROCEDURE`. One requirement is conditional `COMMIT`/`ROLLBACK` of sub-work inside the routine. Callers today use `SELECT my_func(...)`.

## Interviewer Prompt
1. Contrast PostgreSQL functions and procedures regarding transaction control and invocation.
2. When does server-side procedural code help, and when does it hide critical logic from app observability?
3. What interface would you recommend for this workflow and why?
