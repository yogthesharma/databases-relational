# Question 059: Schema Design: Inheritance vs Composition

## Context
A legacy schema used PostgreSQL table inheritance for "base person" and child types. New features need FKs to "any person subtype" and consistent constraints. Team considers collapsing to single-table or class-table composition.

## Interviewer Prompt
1. What practical limitations of inheritance bite application developers (FKs, indexes, uniqueness)?
2. Compare single-table vs joined-table inheritance patterns implemented without PG inheritance.
3. Migration strategy from inheritance to an explicit model with minimal downtime?
