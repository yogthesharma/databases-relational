# Question 056: Exclusion Constraints Beyond Booking Calendars

## Context
Besides room bookings, product wants to ensure a user cannot have two active subscriptions with overlapping validity ranges. Status transitions also matter.

## Interviewer Prompt
1. Model this with ranges + exclusion constraints (and any partial-index predicates you need).
2. What race conditions remain if status flips from active to canceled?
3. Compare enforcing this in the DB versus a transactional application workflow only.
