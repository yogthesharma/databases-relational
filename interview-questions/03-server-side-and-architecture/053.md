# Question 053: Partitioning for Time-Series Retention

## Context
A 5TB `events` table must retain 90 days hot and archive/drop older data. Queries almost always filter `event_time`. Deletes of old data currently take hours and bloat indexes.

## Interviewer Prompt
1. Design range partitioning by time and explain partition pruning.
2. How does dropping a partition compare to `DELETE` for retention?
3. What application and unique-constraint constraints complicate partitioning?
