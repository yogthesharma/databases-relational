# Question 065: Row Level Security Combined with Joins and Views

## Context
RLS is enabled on `tickets` and `ticket_comments`. A reporting view joins them. Some queries run as a bypass role for admin exports; others as tenant roles. Unexpected empty joins and surprising planner behavior appear.

## Interviewer Prompt
1. Explain how RLS policies apply when views/joins touch multiple protected tables.
2. What security bugs appear with `SECURITY BARRIER` views or leaky functions?
3. How would you structure admin break-glass access without disabling RLS globally?
