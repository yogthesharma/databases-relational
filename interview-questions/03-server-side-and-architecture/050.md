# Question 050: RLS for Multi-Tenant SaaS

## Context
A multi-tenant B2B app stores all tenants in shared tables. Today every query includes `WHERE tenant_id = $1`. Breaches have occurred when a query forgot the predicate. You are asked to evaluate Row Level Security.

```sql
CREATE TABLE tickets (
  id         bigserial PRIMARY KEY,
  tenant_id  uuid NOT NULL,
  subject    text NOT NULL,
  body       text NOT NULL
);
```

## Interviewer Prompt
1. Design an RLS policy model using `current_setting` / session variables for tenant context.
2. Explain how table owners, `BYPASSRLS`, and `SECURITY DEFINER` functions can accidentally defeat RLS.
3. What testing strategy proves a new query cannot read cross-tenant rows?
