# Question 052: LISTEN/NOTIFY for Near-Real-Time Fanout

## Context
A dashboard should refresh when new rows land in `alerts`. An engineer proposes `NOTIFY` from a trigger and a Node listener using `LISTEN`. Another proposes polling every 2 seconds.

## Interviewer Prompt
1. Describe delivery guarantees and payload limits of `LISTEN`/`NOTIFY`.
2. What happens under reconnects, poolers (especially transaction pooling), and missed notifications?
3. When is NOTIFY appropriate versus a proper message queue?
