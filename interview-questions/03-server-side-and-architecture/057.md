# Question 057: Enums, Check Constraints, and Evolving Domains

## Context
`order_status` was created as a PostgreSQL `ENUM`. Product now ships statuses weekly. Migrations that alter enums lock awkwardly; ORMs struggle. Alternative: `TEXT` + `CHECK` or lookup table.

## Interviewer Prompt
1. Trade off ENUM vs CHECK vs lookup table for evolving status domains.
2. What lock/behavior issues arise when altering ENUMs in hot tables?
3. Which approach would you standardize on for a rapidly changing product taxonomy?
