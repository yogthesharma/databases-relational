# Question 051: SECURITY DEFINER Functions and Privilege Escalation

## Context
To allow least-privilege app roles to perform a privileged cleanup, someone creates a `SECURITY DEFINER` function owned by a superuser. The function accepts dynamic table names and builds SQL via string concatenation.

## Interviewer Prompt
1. Explain `SECURITY DEFINER` vs `SECURITY INVOKER` and the escalation risk.
2. What hardening practices (owner, `search_path`, fixed SQL, grants) are mandatory?
3. Why is dynamic SQL inside definer functions especially dangerous?
